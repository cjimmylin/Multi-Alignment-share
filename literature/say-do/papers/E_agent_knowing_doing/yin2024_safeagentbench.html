Yin et al. (2024/2025): SafeAgentBench: A Benchmark for Safe Task Planning of Embodied LLM Agents

Citation. Yin, S., Pang, X., Ding, Y., Chen, M., Bi, Y., Xiong, Y., Huang, W., Xiang, Z., Shao, J., & Chen, S. (2024). SafeAgentBench: A Benchmark for Safe Task Planning of Embodied LLM Agents. arXiv:2412.13178 (v5, Oct 2025). Venue. Preprint on arXiv. I did not verify peer-reviewed publication from the PDF. URL. https://arxiv.org/abs/2412.13178 · https://github.com/shengyin1224/SafeAgentBench PDF downloaded. Yes: yin2024_safeagentbench.pdf.

Say–do construct

This is an act-mode benchmark set in an embodied household simulator (an AI2-THOR-based "SafeAgentEnv"). - Safe behaviour: an agent behaves safely if it rejects a hazardous instruction or fails to carry it out. - Unsafe behaviour: it behaves unsafely if it plans and executes the hazard, for example heating a cellphone on a stove. - Scoring: an execution evaluator checks goal conditions in the simulator, which is mechanical. A semantic evaluator (GPT-4) judges whether the generated plan would complete the hazard.

There is no separate test of whether the agent knows the task is hazardous. Rejection rate stands in for "safety awareness".

Method, environment, models

  • Dataset: 750 tasks covering 10 hazard types (fire, electrical, etc.) and 3 task types:
  • detailed tasks;
  • abstract tasks, each with 4 levels of abstraction;
  • long-horizon tasks, where a safety step is needed midway.
  • Agents: 9 embodied agent frameworks (ReAct, ProgPrompt, LLM-Planner, CoELA, MLDT, PCA-EVAL, etc.), each driven by GPT-4 and three open-source LLMs.

Key quantitative findings

  • Detailed hazardous tasks: the most safety-aware baseline, GPT-4 ReAct, rejects only 10% (§1, abstract).
  • Abstract hazardous tasks: the same agent rejects 32%. Rejection rises as the hazard description becomes more abstract (Fig. on abstraction levels L1→L4).
  • Long-horizon tasks: the best baseline (ProgPrompt) completes safely in only 50% of cases.
  • Choice of LLM: GPT-4 and three open models differ by less than 3% in average proactive defence rate on detailed hazardous tasks.
  • Defences: simple defence strategies were ineffective.

Authors' explanation

Embodied agent frameworks are built to optimise planning success, and safety awareness does not carry over from the LLM into the agent framework. Concrete, step-by-step instructions bypass risk recognition more than abstract ones do.

Limitations

  • The simulator's state space is limited.
  • Semantic evaluation relies on GPT-4.
  • There is no chat-mode or QA comparison, so the paper does not show that the LLMs know the hazards.
  • Hazards are physical household risks, not value trade-offs.

Relation to our finding

SafeAgentBench is listed because the brief asked for it. It does not compare judge mode with act mode. The abstraction effect is suggestive for us: rejection is higher when the hazard is described abstractly, which echoes Tang et al.'s knowledge–identification gap, where abstract framing aids recognition. That fits the idea that concrete operational framing pushes agents into "execution mode".

It measures actions only, so it does not separate stated reasons from actions.

Annotation

SafeAgentBench tests 9 embodied agent frameworks, each with 4 LLMs, on 750 household tasks containing 10 hazard types. Task completion is scored by simulator goal checks and GPT-4 plan judgments. The safest configuration rejected only 10% of explicit hazardous tasks (32% when hazards were described abstractly), and swapping the LLM barely changed safety. It shows weak act-mode safety in embodied planning but has no judge-mode comparison.
