Zhan et al. (2024): InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated Large Language Model Agents

Citation. Zhan, Q., Liang, Z., Ying, Z., & Kang, D. (2024). InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated Large Language Model Agents. Findings of ACL 2024. arXiv:2403.02691. Venue. Findings of ACL 2024 (peer-reviewed). URL. https://arxiv.org/abs/2403.02691 · https://github.com/uiuc-kang-lab/InjecAgent PDF downloaded. Yes, zhan2024_injecagent.pdf

Say–do construct

This paper measures act mode only, under attack. An attack succeeds when the agent's parsed output shows it invoked the attacker's tool. For data stealing, success means both extracting the data and sending it to the attacker. Scoring is mechanical, from the parsed tool invocations (§3.1). Nothing is measured on the say/know side. The paper is included because the brief asked for it, and because it is an early example of scoring agent actions mechanically from tool calls.

Method, environment, models

  • Test set. 1,054 test cases using 17 user tools and 62 attacker tools, built on ToolEmu-style tool specifications. Attack intents fall into two groups: direct harm to the user, and exfiltration of private data.
  • Settings. In the base setting, the attacker instruction is embedded in a tool response. In the enhanced setting, a "hacking prompt" is added to it.
  • Agents. 30 LLM agents, either ReAct-prompted (GPT-4, GPT-3.5, Claude-2, Llama2-70B, and others) or fine-tuned for function calling (the GPT-4 and GPT-3.5 function-calling variants).

Key quantitative findings

  • ReAct-prompted GPT-4. ASR-valid is 24% in the base setting and 47% in the enhanced setting (§3.2, Table 3).
  • Prompted Llama2-70B. ASR exceeds 80% in both settings.
  • Fine-tuned agents. These are more resilient: GPT-4 at 3.8% and GPT-3.5 at 6.6%.
  • Effect of the hacking prompt. It raises ASR for every agent except prompted Claude-2.
  • Attack type. Data extraction (step S1) succeeds more often than direct-harm tool execution.

Authors' explanation

Agents fail to separate the user's instructions from instructions found in external content. Fine-tuning on tool use appears to improve this separation.

Limitations

  • Simulated tool responses.
  • Single-turn injection points.
  • Unoptimised attacks, so the reported rates are a lower bound.
  • No measurement of whether the agent recognised the injection.

Relation to our finding

The connection is limited. InjecAgent is about following instructions from an untrusted source, not about knowingly violating a stated priority. Its value for our paper is methodological: it scores actions mechanically from tool invocations, as we do. It also connects to the instruction-hierarchy literature, since an injected instruction should rank below the user and the system. A later paper in this strand reports that agents can detect injected or forged instructions yet still execute them: Leong et al. 2026, arXiv:2608.28502, noted but not downloaded.

Annotation

InjecAgent's 1,054 cases test whether tool-using agents execute attacker instructions embedded in tool outputs. Attack success is scored mechanically from parsed tool calls. ReAct-prompted GPT-4 was compromised 24% of the time (47% with a hacking prompt), while function-calling fine-tuned models were far more robust (3.8–6.6%). It is a security benchmark with no say channel, relevant here mainly as precedent for mechanical action scoring and for instruction-priority failures.
